W2T 固定腿构型平衡控制说明

适用模型
  bitbot_w2tROBOT.xml + models/w2tROBOT.xml；模型采用已校准的 1.49° 初始前倾姿态。
  股骨 30°、胫骨 -60°、NUT 滑块 0 m；本次只做该构型的原地平衡。
  总质量约 31.24 kg，轮半径 0.138 m，左右 ATS 轴间距约 0.304 m。
  只调整 torso 的初始 pos/quat；质量、惯量、关节构型、轮形及接触参数不变。

方法选择
  选择串级 PID：轮位移 P -> 轮速度 PI + 固定平衡角前馈 -> 机身俯仰 PD -> 双轮力矩。
  另有偏航 PD 和腿关节姿态 PD。内环不加积分，避免倾倒时积累力矩。
  该模型包含闭链约束和分段轮面接触，先用 PID 可以直接依靠 IMU、关节
  反馈调试；LQR 需要进一步验证平衡点及其线性化动力学，并非只换一组增益。
  当前轮位置是编码器里程估计，包含机身及腿转角补偿，不是外部定位。

文件
  main.cpp：配置路径查找、状态机和事件注册。
  user_func.h：控制参数、状态、监测量及接口声明。
  user_func.cpp：设备检查、控制、限幅和故障处理。
  backend.json：前端按键与后端事件映射。
  tests/balance_smoke.cpp：通过实际 Bitbot 设备接口运行无界面 MuJoCo 测试。
  tests/balance_validation.txt：本次编译和动力学验证结果。

后续阅读与修改
  先看 main.cpp 的状态/事件注册，再看 user_func.h 的参数单位和 UserData，
  最后按 user_func.cpp 中 StateBalance 的 1~8 步理解每周期控制流程。
  backend.json 是标准 JSON，不能加入 // 或 /* */ 注释；字段含义如下：
  event 对应 main.cpp 注册的事件字符串（或内核内置事件），kb_key 对应前端
  KeyboardEvent.key 的精确值，区分大小写；空格键必须写成单个空格字符串。
  改键位时保持 event 不变；新增功能时同时添加事件回调、注册和状态许可列表。

编译与运行（在项目根目录的 PowerShell 中）
  cmake --build build --config Release --target main_app
  .\build\bin\Release\main_app.exe
  程序也可从 build/bin/Release 或 Debug 目录启动，自动查找项目 XML。
  可显式指定配置：main_app.exe F:\bitbot-mujoco-demo\bitbot_w2tROBOT.xml

前端
  打开 F:\bitbot-frontend-win-x64-0.0.1-portable.exe（已核实版本 0.0.1），
  连接本机后端 127.0.0.1:12888。
  按键由后端 backend.json 提供；修改后重启后端并重新连接/刷新前端。
  连接成功后，必须点击“点击此处进行控制”输入框，显示“控制中”后再按键。
  按键到松键期间保持该输入框焦点；b、m 使用小写，不是在 MuJoCo 窗口按键。
  已核对实际 EXE 内的源码协议；上一版还进行过实际后端 WebSocket 报文回放。
  tests/frontend_protocol_validation.json 保留该历史记录，其中微调事件现已删除，
  不能将历史记录视为本版的全部验证。当前控制与键位检查见 balance_validation.txt。
  界面截图工具超时，未完成鼠标端到端验证。
  框架说明：https://bitbot.lmy.name/docs/intro/

按键（自定义事件均在松键时触发一次）
  8      从初始暂停状态开始仿真，直接进入平衡。
  5      解除控制，所有关节输出零力矩；此状态不能保持站立。
  b      从解除控制状态重新进入平衡；只允许接近直立的姿态。
  m      开始 CSV 记录，保存于 log/data；原框架此键不是开关。
  空格   内核停止；本版本框架停止后不能用 8 恢复，须重启后端。
  原 1、2 是调试俯仰参考的微调键，不是前进/后退；现连同 0 复位键及回调一起删除。
  已调参数直接保存在 BalanceParameters 中，运行时不再需要人工按键修正平衡角。
  MuJoCo 窗口内的 Run/空格只控制仿真推进，不能代替前端 8 启动后端平衡状态。
  完整复位请重启后端。MuJoCo 的 Reset 不会重新施加 Bitbot XML 中 30/-60/30°
  的腿部/轮轴初值，也不会清除控制器历史；时间回退会触发保护，不能替代后端重启。
  模型重载或拖入新模型时也请重启后端；原框架重载流程没有完整重绑设备指针。

参数与单位
  user_func.h 的 BalanceParameters 集中设置外环、俯仰、偏航参数。
  user_func.cpp 的 kPose/kJointKp/kJointKd 设置固定腿构型及关节 PD。
  代码角度使用 rad；前端 extra 的 *_deg 使用度；速度使用 m/s。
  XML 中的位置模式在 ConfigFunc 中被切换为力矩模式，原示例 28000
  位置增益不参与控制；XML 仍用于设备映射及初始姿态。
  ATS 的 gear=6：SetTargetTorque 输入的是 ctrl，轮端 Nm 必须除以 6。
  extra 中 right_wheel_Nm/left_wheel_Nm 是已换算的轮端力矩。
  正俯仰向模型 +X 前倾，双轮正关节轴均为 -Y；代码已按此设置反馈符号。
  因重心偏置、腿部柔性及轮地接触，正常稳态并非严格零俯仰；
  本版默认初态 120 s 测试末段约为前倾 1.46°，不是必须回到零度。
  pitch_equilibrium=0.026 rad（约 1.49°）是此构型的已标定前馈，速度 PI 继续修正残差；
  它不是运行中可调的微调量，也不表示实测俯仰必须恰好等于 1.49°。
  偏航 Kp=20 Nm/rad、Kd=5 Nm/(rad/s)，参考航向在启动时捕获；
  陀螺仪机体系角速度转换为欧拉偏航角速度后再参与阻尼计算。
  position_deadband=0.005 m 是编码器位置的连续容差：
  position_error = position - clamp(position, -0.005, +0.005)。
  容差内目标速度为零，容差外只对超出部分产生回位速度，边界处连续；
  速度反馈、俯仰/偏航控制及已有积分补偿始终保留。该容差不等于机身世界定位精度。

复位姿态为何需要调整
  原先机身零俯仰、关节处于 30/-60/30° 初值时，整机质心为
  (0.0375213, 0.0013413, 0.6058758) m，双轮轴中点为 (0.054, 0, 0.1383848) m。
  质心比轮轴后移约 16.48 mm，向上相距约 467.49 mm；竖直机身并不代表整机已经平衡。
  未承重几何的对齐角 = atan2(16.48, 467.49)，约为向前 2.0188°。
  但腿部靠有限刚度 PD 承重后，股骨约从 30° 变为 29.83°，胫骨约从 -60° 变为
  -60.69°，接触也会下沉；带载平衡附近约为小幅前倾 1.5～1.6°，还与轮地接触和
  轮端静态力矩有关，不能只按未承重几何角设置控制目标。

方案工作量与最终选择
  方案一：调整整个机器人的初始 root 姿态。只需修改模型 torso 的 pos/quat 两个属性，
  保留当前控制结构、关节构型和前端状态，改动最少；本版采用此方案。
  方案二：调整双侧股骨初始角使机身保持竖直。需要同时修改 Bitbot initial_pos、
  腿部 PD 参考角和负载平衡目标，并重新验证构型及接触，工作量更大。
  方案三：继续从零俯仰启动、依靠控制器完成姿态迁移。已有前馈能明显改善，
  但不如直接接近平衡姿态启动；本轮无需新增控制状态或重新设计 PID/LQR。
  最终采用初始前倾 1.49°，与现有 pitch_equilibrium=0.026 rad 基本一致。
  复位角决定“从哪里开始”，平衡前馈决定“控制器要保持哪里”，二者应配合；
  改了复位角后不能把平衡前馈清零，否则控制器仍会要求机器人回到不合适的零俯仰。
  配套的小改动是位置环默认允许 +/-5 mm 残差，避免在已经站稳后持续追赶毫米级误差。

复位参数与修改方式
  models/w2tROBOT.xml 中 torso 使用：
    pos="0.016441817977566824 0 0.77119057093888499"
    quat="0.99991546604931647 0 0.013002336535343549 0"
  四元数顺序为 w,x,y,z；绕 +Y 转动表示向 +X 前倾。
  位置由 p_new = axle + Ry(theta) * (p_old - axle) 计算，其中
  p_old=(0,0,0.77)，axle=(0.054,0,0.138384757729)，theta=1.49°。
  pos 与 quat 必须一起修改，使轮轴初始位置及约 0.385 mm 离地间隙保持一致；
  只改 quat 会让轮子提前压入地面，使角度对比混入落地高度的影响。
  现在未承重质心仍在轮轴后约 4.32 mm，这是结合实际承重过程选择的起始姿态，
  不宣称它就是未承重质心严格对齐的静态解。承重后质心与轮轴的偏差进一步缩小。

初始姿态的筛选依据（加入位置容差之前）
  保持原控制参数不变，使用实际 Bitbot 总线运行 30 s；位移相对各自初始躯干位置：
    初始俯仰            机身世界 X 位移范围                 最大偏航
    原零度              -8.22 ～ +20.95 mm                  0.07690°
    1.49°（采用）       -0.43 ～ +1.29 mm                   0.04974°
    1.60°               -6.31 ～ +13.87 mm                  0.09603°
    2.0188°几何对齐     -15.43 ～ +5.68 mm                  0.12915°
  非零角候选均保持原轮轴位置和初始离地间隙，不通过接触压入或重设运行原点减少表面位移。
  这些是躯干指标，轮轴还会因腿部负载变形而移动；不应理解为轮子完全不滚动。
  仅修改初始姿态时，延长至 60 s 仍会出现一次约 17.92 mm 的机身偏移：
  静止阶段编码器约 -4.793 mm，位置环持续产生 +1.198 mm/s 的目标速度，
  速度积分缓慢增长，约 51.7 s 后产生移动。这能从位置、速度和目标俯仰时序直接确认；
  未记录具体接触点，不能据此断言发生了哪一轮段的接触切换。
  因此最终版本同时加入上述连续位置容差；仅微调平衡前馈可能只是改变出现移动的时刻。
  最终版本（1.49° 复位 + 0.026 rad 前馈 + 5 mm 位置容差）连续 120 s 测试通过：
    机身纵向位移范围 -0.46 ～ +0.30 mm，最大水平位移约 0.51 mm；
    轮轴纵向位移范围 -6.41 ～ 0 mm，末值约 -4.78 mm；最大偏航 0.03549°；
    末 2 s 轮速峰值 0.00008 m/s，无控制故障。
  同一模型关闭位置容差的 60 s 对照仍复现 17.92 mm 偏移，说明容差针对的是持续积分来源。
  最终版本的长期指标、轮轴运动及回归结果见 tests/balance_validation.txt。
  编码器里程、机身世界坐标、轮轴世界坐标是不同量，测试同时检查实际运动和全过程峰值。

保护与监测
  轮端力矩上限 ±40 Nm，变化率上限 500 Nm/s，并再次受模型 ctrlrange 限制。
  积分限幅及饱和抑制；目标俯仰限制约 ±6.88°。
  启用时要求 |pitch|<=10°、|roll|<=8°；运行时阈值分别为 30°、20°。
  fault_code：1 非有限传感器值；2 姿态越限；3 轮速估计超过 2.5 m/s；
              4 仿真时钟回退或控制间隔异常。
  故障时清零全部输出并请求内核停止；故障锁存，必须重启后端恢复初态。
  建议观察 pitch_deg、pitch_target_deg、yaw_deg、yaw_target_deg、wheel_velocity_mps、左右轮力矩、
  balance_active 和 fault_code。

  ctest --test-dir build -C Release --output-on-failure
  .\build\bin\Release\balance_smoke.exe --scenario startup --duration 30

  具体场景、判据、编译结果和长时间测试记录见 tests/balance_validation.txt。
  这套参数用于当前模型默认初始高度的固定腿平地平衡，尚不覆盖变形、行走或实物控制。
  任意抬高机器人再落地不属于本版支持的启动方式；离地探针与保护结果见验证报告。
  若以后需要空中启动/跳跃落地，应单独增加接触状态与离地控制逻辑。
